## 一、数据库优化

### 1.1 索引优化

**优化目标**：
- 核心查询 SQL 执行时间 < 50ms
- 索引覆盖率 >= 95%

**优化措施**：
1. 为常用查询字段添加索引
2. 建立复合索引优化多条件查询
3. 定期分析慢查询日志

**待执行 SQL**：
```sql
-- 支付订单索引
CREATE INDEX idx_payment_order_no ON t_payment_order(order_no);
CREATE INDEX idx_payment_user_id ON t_payment_order(user_id);
CREATE INDEX idx_payment_status ON t_payment_order(payment_status);

-- 理赔申请索引
CREATE INDEX idx_claim_no ON t_claim(claim_no);
CREATE INDEX idx_claim_user_id ON t_claim(user_id);
CREATE INDEX idx_claim_status ON t_claim(claim_status);

-- 消息索引
CREATE INDEX idx_message_user_id ON t_message(user_id);
CREATE INDEX idx_message_status ON t_message(status);
```

### 1.2 SQL 优化

**优化原则**：
- 禁止 SELECT *
- 避免 JOIN 超过 3 张表
- 使用 EXISTS 代替 IN
- 使用 UNION ALL 代替 UNION

## 二、缓存优化

### 2.1 缓存策略

| 数据类型 | 缓存策略 | 过期时间 |
|---------|---------|---------|
| 用户信息 | 本地+Redis 二级缓存 | 5 分钟 |
| 字典数据 | 本地缓存 | 10 分钟 |
| 服务列表 | 本地缓存 | 30 秒 |
| 支付订单 | Redis 缓存 | 1 小时 |

### 2.2 缓存穿透防护

**措施**：
1. 布隆过滤器过滤不存在的 key
2. 空值缓存（过期时间 5 分钟）
3. 接口层参数校验

### 2.3 缓存雪崩防护

**措施**：
1. 缓存过期时间添加随机值（±5 分钟）
2. 热点数据永不过期
3. 多级缓存架构

## 三、代码优化

### 3.1 并发优化

**措施**：
1. 使用线程池管理线程
2. 异步处理非核心逻辑
3. 使用 CompletableFuture 并行调用

### 3.2 连接池优化

**配置**：
- HikariCP: max=20, min=5, timeout=30s
- Redis: max=16, min=2, timeout=1s
- OkHttp: max=16, timeout=5min
