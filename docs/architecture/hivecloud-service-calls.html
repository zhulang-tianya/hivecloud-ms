🔄 典型业务流程

🔐 用户登录流程

  1. 用户 → Gateway: 提交登录请求
  2. Gateway → System: 转发认证请求
  3. System → MySQL: 查询用户信息
  4. System → Redis: 缓存用户信息
  5. System → Gateway: 返回 JWT Token
  6. Gateway → 用户：返回登录结果

💳 支付流程

  1. 用户 → Gateway: 发起支付请求
  2. Gateway → Payment: 转发支付请求
  3. Payment → MySQL: 创建支付订单
  4. Payment → 微信/支付宝：调用支付接口
  5. Payment → Notify: 发送支付成功通知
  6. Notify → 短信 API: 发送短信
  7. Payment → Gateway: 返回支付结果

📝 理赔流程

  1. 用户 → Gateway: 提交理赔申请
  2. Gateway → Claim: 转发理赔申请
  3. Claim → MySQL: 保存理赔记录
  4. Claim → System: 查询用户信息
  5. Claim → Notify: 发送理赔通知
  6. Notify → 短信 API: 发送短信
  7. Claim → Gateway: 返回申请结果

🎁 活动参与流程

  1. 用户 → Gateway: 参与活动请求
  2. Gateway → Activity: 转发活动请求
  3. Activity → Redis: 检查参与资格 (限流)
  4. Activity → MySQL: 记录参与信息
  5. Activity → Notify: 发送活动通知
  6. Notify → 短信 API: 发送短信
  7. Activity → Gateway: 返回参与结果

⚙️ 技术实现说明

服务间调用

  • 使用 Spring Cloud OpenFeign 进行服务调用
  • 支持负载均衡和熔断降级
  • 声明式 API 调用，代码简洁

服务注册与发现

  • 使用 Nacos 作为注册中心
  • 服务启动时自动注册
  • 支持服务健康检查和自动摘除

配置管理

  • 使用 Nacos Config 统一管理配置
  • 支持配置热更新
  • 通过 Namespace 实现环境隔离

认证鉴权

  • 使用 JWT 进行身份认证
  • Gateway 统一鉴权
  • 服务间调用传递用户上下文

限流降级

  • 使用 Redis + Lua 实现限流
  • Gateway 层全局限流
  • 支持服务降级和熔断

日志追踪

  • 使用 Sleuth + Zipkin 实现链路追踪
  • 每个请求生成唯一 TraceID
  • 便于问题排查和性能分析
